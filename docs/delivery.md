# Delivery and meaningful completion

Deliver the concrete requested artifact or authorized existing PR and verify the delivery result. Preserve artifact path/link, version/digest, recipient/destination, operation identity, returned result and scope. A local artifact is valid delivery when local delivery was requested and the recipient can use its supplied path. An externally requested upload needs its own confirmed receipt; a local file does not substitute for it.

A worker completion event enters the existing coordinator's intake. It does not close the original request. The accountable owner integrates the result, obtains any required independent acceptance, verifies the destination receipt and returns the bounded delta to the sole register writer. If the send is uncertain, use recovery; no duplicate send for reassurance.

Report local checks, independent review, hosted CI, merge, release, live runtime and customer usefulness as separate states. Product acceptance can remain open after a successful artifact delivery. A test purchase is not retained revenue. A successful HTTP response, provider execution or settlement with an unusable output does not pass useful-result acceptance.

For a percentage, name the stable population, numerator, denominator, observation time, source revision and what the fraction measures. Never add overlapping chats, derived prompts, issues, PRs, requirements or theorems into one score. When the total required set is undefined, report Unknown/unverified. Keep partial success visible without making it whole-product completion.

Finish when the finite original outcome is delivered and accepted, or report the exact remaining dependency and its owner/resumption trigger. Carry authorized repairs through that point without asking the user to repeat instructions. No new audit or recurring management pass is created merely because a plan or report was completed.

Use [contract-specific handoff stages](completion-contract.md) to distinguish persistence, attachment, recipient readback, and canonical incorporation or retained disposition. Required multipart outcomes and native-goal completion/readback remain separate from artifact delivery.

Return [the feature checklist](execution-plan.md) with all required main features/extensions and VM's final combined-subject verdict. Preserve open states and their resumption conditions. A reviewable local package can satisfy local delivery while live observations, remote proof runs, held-out evaluation or publication remain explicitly unperformed.
