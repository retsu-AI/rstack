# Review an authorized account and device estate

Use the existing security owner for a user-defined estate review. Keep repository application-security reviews with their own domain skills. This procedure accounts for real assets, accounts, devices and active runtimes without starting an unrequested audit.

## Set the coverage boundary

Record the authorized asset classes, owners, access methods, review period and permitted actions. Preserve active holds, intentionally retained remote access and file workflows. A missing native goal or older audit instruction does not authorize resumption.

Use stable private asset references. Capture relevant product, build, firmware, runtime or grant metadata without copying credentials or unnecessary personal details. A grouped inventory row is not evidence for every device or account in the group.

## Assess each claim

1. Distinguish declared configuration, installed package and actual loaded runtime. A package update does not establish that the running service adopted it.
2. During the authorized audit, consult current primary advisories and official product documentation. Match exact product, component, build range, configuration and required conditions. Preserve the source and observation date.
3. Classify evidence precisely. Outdated means behind the applicable update baseline. Affected means an advisory matches. Exposed needs the relevant reachable or enabled path. Demonstrated compromise needs evidence of unauthorized activity, not an old version alone.
4. Keep account recognition, network reachability, authentication, useful data access and isolation separate. A recognized session or successful sign-in is limited evidence.
5. Preserve unknown fields and failed queries as gaps. A short traffic observation or absent advisory match does not establish universal safety.
6. Return findings to the existing owner. Perform updates, revocation, scans or containment only within current action authority, preserving data and dependencies. Verify the actual changed runtime and intended useful access afterward when authorized.

Do not disable a working capability to make an audit result appear safer. If recovery evidence is required, separate backup coverage and representative restore from security acceptance.

## Return evidence and acceptance

Return a private asset-and-coverage register with exact inspected versions, dated source applicability, observation method, conclusion, uncertainty, owner and next action. Use [verification](verification.md) for source-bound independent review where required. Report the denominator by actual inspected assets and account boundaries.

| Case | Required result |
|---|---|
| Normal | An exact build and enabled condition match a primary advisory. Record the narrow affected or exposed finding and the authorized owner's next action, preserving intended access. |
| Reject | One outdated package, an unfamiliar label or a failed API query cannot yield a whole-estate compromised or safe verdict. |
| Incomplete | A device's firmware field is unavailable. Retain that device as an explicit coverage gap rather than copying another device's result. |
| Hold | A later user pause or retired asset prevents new audit actions even when an earlier plan remains unfinished. |

This reference asserts no current vulnerability, account status or remediation result. Keep raw security evidence private and minimize reusable reports.
