# Qualify mailbox triage and rules

Use this procedure for the requested account and bounded folders, time range or selected messages. Prefer a capable connected mail tool. Use the requested browser when necessary. Reuse the existing owner, and keep one writer for mailbox changes.

## Establish the population

Record account identity through nonsecret metadata, exact message or thread IDs, selected folder coverage, pagination, requested labels or pins, sender exceptions and the current action authority. Read full relevant threads, including sent replies. Unread does not mean unanswered.

Preserve active obligations, receipts and security codes. Distinguish authentic from wanted mail. A sender the user intentionally blocked remains blocked unless the user changes that choice. Leave uncertain classification unchanged.

## Classify, apply and read back

1. Prepare a disposition for each selected message or thread. Require a non-author verdict on consequential classifications before bulk filing, archiving, marking spam or blocking. Give the reviewer the original criteria, necessary thread context and authorized action scope. Read-only summaries and tentative classifications need no extra review unless the task requires it.
2. Apply only the authorized action to the reviewed identities. Preserve unrelated topic labels and pins. Check whether the provider's move operation replaces labels rather than adding a folder.
3. Read back the exact affected IDs and labels. Reconcile an uncertain move or write before retrying.
4. For a rule, verify the saved account, predicates, priority and action. Check relevant exceptions, overlap and the provider's actual forwarding or filtering behavior.
5. Qualify new-arrival behavior using a benign existing or separately authorized test message. Record source headers, destination identity, original retention and the actual arrival result. Sending a test or enabling forwarding still needs its existing scoped authority.

Incoming forwarding does not establish historical import, Sent or Spam synchronization. A provider login does not prove forwarding authorization. Do not add another account, paid source or recurring cleanup merely to complete a bounded filing task.

## Return evidence and acceptance

Return the reviewed population and coverage gaps, dispositions, independent verdict where required, exact changed identities, before-and-after labels, saved rule and observed arrival receipt. Keep cleanup completion and ongoing rule acceptance separate. Use [delivery](delivery.md) when recipient receipt is part of the requested outcome.

| Case | Required result |
|---|---|
| Normal | A reviewed wanted receipt retains its required label and pin. A qualified rule routes an authorized newly arriving message to the correct destination while preserving the original as requested. |
| Reject | A bulk action that hides an unresolved obligation, removes an unrelated label or re-enables a deliberately blocked sender fails acceptance. |
| Incomplete | The saved rule matches a search, but no new message has arrived. Report static configuration and leave arrival behavior unobserved. |

Keep private message bodies and account details in their authorized store. Reusable reports need only the minimum evidence pointers.
