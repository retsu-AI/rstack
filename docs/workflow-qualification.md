## History-to-skill review

Freeze a UTC start/end and enumerate the host-aware active and archived history until crossing the start. Page each selected chat to history end or the earlier boundary. Retain the real host, thread, cursor, original turn times and stopping evidence privately. A recent rename, import or settings change is not new substantive work. Retry an oversized page once with the documented smaller turn limit and outputs excluded. If a single turn remains unreadable, record the exact gap without guessing its contents.

Read the original request, later corrections and reported results. Separate message prose, tool output, attachments and external source coverage. Active turns without message timestamps cannot establish exact-cutoff events. Compare maintained skill bodies before choosing reuse, a narrow update or a distinct new procedure. Keep private examples and source identities outside reusable source. Return one disposition per selected chat and an explicit denominator.

## Planning and phase boundaries

Research paths, interfaces and existing owners before asking questions. Ask only when an unresolved fact or preference materially changes the result and cannot be discovered. Make routine reversible choices within current authority. A reference to another planning skill does not make its question template mandatory.

Preserve main features, extensions, prerequisites and concrete rejecting acceptance in the existing [execution plan](execution-plan.md). Authorized design, notes and formal modeling may proceed before code exists. Source-conformance and runtime acceptance wait for the actual implementation. Preserve unrelated edits during integration; distinguish startup or billing failures from failed product tests.

## Benchmark admission and grader adequacy

Read [benchmarks](benchmarks.md) before an evaluation. Admit an attempt only after the actual task prompt, isolated subject and selected treatment are loaded. Saved plugin configuration does not prove the worker used it. Separate pilot fixture development from frozen held-out selection.

Qualify the reference solution and legitimate alternatives. Require rejecting controls for no-op work, forged scores, answer copying, invalid output formats and required operations. Inspect the action trace when forbidden intermediate effects matter. A numerically close answer or correct final state may still violate the task. Preserve setup, quota and transport failures separately from task grades. A requested comparison, a chart or selected failures do not establish measured superiority.

## Causal evidence and measurement

Review the checker's adequacy independently before trusting its verdict. Identify the nonempty target population, actual causal trigger, expected postcondition and an oracle independent of the implementation's own declaration. Retain shared finding IDs through diagnosis, repair and changed-revision review.

For live campaigns, bind executable, exclusive slot where required, checker configuration and source revision. Separate wrapper, collector and checker outcomes. Use failure-specific bounded retries and verifier resource limits. Pin event identity, stage boundaries and valid initialized cohorts before warmup. Do not substitute socket age for participant age, invent timestamps or plot unobserved runs. Report missing populations, stale receipts and unverifiable causes as gaps.

## Transport, retries and spend

Read [benchmarks](benchmarks.md) for model-versus-harness controls. Rehearse the actual pinned command-line tools against synthetic providers before an authorized paid comparison. Exercise the production SDK/transport boundary, default route, valid request and rejection controls. Include response-withheld ordering when it affects correctness. Record architecture or emulation and preserve setup failures.

Enumerate every layer that can generate a request, including SDK retries, worker recovery and rescheduling. Reconcile prior actual or unknown usage and outstanding reservations before allocating more work. Unknown release of a reservation remains unknown. A prompt saying a cap is not enforcement. Keep artifact production, provider acceptance and native task/checker achievement separate. Configuration or an existing key does not authorize spending.

## Current host and Cloud capabilities

Discover current native tool schemas and installed CLI help before selecting flags, environment selectors or permissions. Record exact requested environment identity, available capability and complete errors. An absent field is unknown, not proof of denial or success.

Distinguish saved configuration, published environment, startup, restoration, authentication, scoped resource access and next-worker adoption. A successful task through a legacy CLI environment does not prove a native published-environment launch. Obsolete grant prerequisites must not invent blockers or authorize security changes. Qualify the actual producer and consumer against pinned source and current documented contracts.

## Independent static adjudication

Use [verification](verification.md) for exact-subject review. For contested static findings, freeze the criterion and subject, bound the challenge, then use a distinct non-author adjudicator. Keep draft or conditional contracts separate from current product obligations. Supply raw evidence rather than the desired verdict; record any necessary blinding exception.

Return accepted corrections to the original writer. Recheck the changed revision within the existing attempt/time budget. Stop with accepted, rejected, blocked or unobserved obligations. Agreement between reviewers does not replace a rejecting check or prove runtime behavior.

## Model selection and actual adoption

Evaluate the full ongoing responsibility, expected reasoning and rework cost. Keep model capability and reasoning effort separate. Use neutral facts and criteria for an advisory selector; preserve abstained, unavailable, ranking-only or below-threshold responses. Do not alter thresholds or candidates merely to force a recommendation.

A temporary administrative step does not justify a persistent downgrade. A blanket maximum is not task-fit evidence either. Preserve the user's effective settings and billing choices. Distinguish advisory response, delivered instruction, saved configuration, reload readback, next actual inference and independently graded useful output. Preserve user-reported regressions as reports until measured. Reconcile changes that revert on reload before claiming application.

## Terminal recovery and safe stop

Use [recovery](recovery.md) and retain original conversation, host, worktree, branch, executable/protocol, effective configuration, authentication and unsent input. Save and restore must address the same per-server snapshot. Inspect the actual stop wrapper, timeout and escalation before calling a stop graceful.

Check each retained workload, not aggregate window/pane/process counts. Exercise process death, server death, partial save, concurrent input, intentional stop and configuration equivalence as applicable. An intentionally closed or paused lane stays closed. A restored interface, scheduled save or isolated restart does not prove usable authenticated work or physical reboot recovery. Preserve client and server ownership during cleanup.

## Backup, storage and cleanup evidence

Distinguish source coverage, transport, committed snapshot, consistency, accepted exceptions, freshness and actual recovery evidence. Include auxiliary records and attachments, not only the main database. Scheduling configured, first scheduled execution and current usable increment are separate observations. Monitoring timeout must not silently cancel a healthy producer.

Classify authoritative state, original setup/source and required secret custody separately from rebuildable job output. Do not accumulate whole-machine rollback copies on repair retries. Separate logical, allocated and uniquely reclaimable physical bytes; avoid overlapping totals and attribute concurrent changes cautiously. Do not divide unrelated progress counters or infer a restarted active copy from the absence of a completed snapshot.

Preserve the latest user scope and exceptions. Do not repeat local restores after a later decision supersedes them. Cleanup selects exact owned rebuildable outputs through existing recovery/storage guidance; measurements are advisory rather than a universal execution gate.

## Review controls and finding closure

Separate connected repository access, personal/shared automatic review policy, manual trigger authority and payer authorization. Do not run a paid review to test access. A bot reply cannot establish whose budget paid for it.

Reconcile each finding with current code, merged or open fixes, archived/history copies and existing owned follow-up. Unresolved threads are not unique bugs or a fix-rate denominator. End with an evidenced fix, linked owned issue or reasoned dismissal. Keep automatic-review settings distinct from current finding disposition and preserve manual holds.

## Architecture, concurrency and durable state

Compare the approved architecture with actual entrypoints and all durable stores. Record deliberate accepted changes. Build or test success does not establish conformance to a different requested architecture. Pin dependency versions and trace actual dispatch, cancellation and finalization behavior.

Exercise late completions, account changes across await, connect/disconnect races, stale generations and partial cleanup. A stale operation must not revive deleted/disconnected state or mutate a different account. One cleanup failure must not suppress unrelated cleanup. Include auxiliary progress and attachments in exports, backups and restore tests. Preserve repeatable evidence rather than relying on ignored local logs.

Use [the formal architecture example](formal-architecture-example.md) when a state machine helps. Keep diagram structure, rendered pixels, mathematical proof and implementation correspondence separate.

## Automation worthiness and recurrence

Use the existing company operating loop. An unfinished project alone does not justify recurring supervision. Identify a useful external change, reply, deadline, expiry or terminal-job condition. Reconcile existing paused/enabled tasks before adding a schedule. A completed one-off does not become an indefinite monitor.

Keep run history in an authorized runbook and retain scope/stop conditions in the active prompt. Read back actual timezone and recurrence; calendar months are not four weeks. Prompt wording does not set an enforced spend limit. Generic review does not resume held work or authorize new recurring actions.

## Browser and native window custody

Use the requested supported control and identify the exact permitted window and current writer. An active agent is not evidence that it owns a browser. Preserve reserved windows, drafts and unrelated tabs. Use fresh scoped state before each consequential action.

Verify search-field focus before typing in messaging interfaces. A read operation must not become an accidental send. Reconcile an uncertain effect before retry or authorized repair. Distinguish runtime reset, tab closure, physical capture release and background recording. End owned capture using supported cleanup without disturbing unrelated shared services.

## Correspondence and staged delivery

Read full threads and sent replies before classifying unanswered work. Unread is not unanswered; identify the latest actual speaker. Preserve original attribution, exact authorized wording, authoritative dates and timezone. Verify account and recipient identity before acting.

Track prepared, approved, submitted/sent, carrier or recipient possession, acknowledgement and final outcome separately when relevant. A shipping purchase is not recipient possession; a rescheduling request is not an accepted appointment. A human-completed send prevents duplicate follow-up. Leave unavailable physical properties, timing or final outcomes unobserved rather than guessing them.

## Replicated independent review

Choose partitioned review for disjoint evidence and replicated review when each reviewer must inspect the same complete population. Supply the full indexed set to each replicated reviewer, with independent rubrics and minimum task-local context. Preserve record/version identity and uncertainty.

Require every reviewer to account for every scoped record. Three disjoint thirds do not satisfy three complete reviews. Reconcile disagreement from original evidence, not by averaging unsupported conclusions. A launch request or running worker is not a returned independent result. Close accepted lanes through the existing owner.

## Context recovery acceptance

Distinguish retained bytes, catalog discovery, session loading, memory ingestion and correct retrieval. Test that recovery retrieves later corrections, holds, completed effects and current ownership. A transcript pointer is useful only if its target remains available and the right evidence is retrieved.

Label native branches, recovery copies and imports accurately. A pin receipt or readable file does not establish adoption or original-session continuity. Preserve inaccessible history as a coverage gap. Never replay an old queued instruction into a live draft or restart a held project from recovered context.

## Canonical identity and handoff

Map canonical product/repository identity separately from historical lineage and compatibility identifiers. Restore original scope and latest steering before status or execution. Do not report unrelated archived work as the current task.

Distinguish instruction sent, recipient acknowledgement, newly created worker, actual action and accepted incorporation. Consolidate overlapping execution under one acknowledged owner. Recheck uncertain effects before replacement, and require changed evidence for another follow-up. Finish the finite unit rather than adding another dispatcher, supervisor or queue.

## Acceptance record

Reuse the existing [execution plan](execution-plan.md) and [qualification evidence template](../templates/qualification-evidence.md). Record criterion, exact subject/configuration, observed evidence, negative control, independent reviewer, corrections and remaining gaps only where relevant. Stale subject acceptance must be reopened. Structural validation, a synthetic exercise and real-service/physical acceptance are distinct evidence states.
