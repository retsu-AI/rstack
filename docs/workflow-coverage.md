# Operating practice coverage

Rstack groups recurring engineering decisions into eight reusable skills. It preserves the original request and current authority without requiring a long copied rule catalog.

| Decision | Practice | Reference |
|---|---|---|
| What counts as finished? | Retain original obligations, multipart scope, current approval and finite acceptance conditions. | [Outcome contract](contract.md), [completion contract](completion-contract.md) |
| Who owns the work? | Keep one accountable writer per artifact, reuse the coordinator and give parallel helpers disjoint paths. | [Coordination](coordination.md), [worker brief](../templates/worker-brief.md) |
| Did execution start? | Distinguish request, admission, first action, artifact, delivery and independent acceptance. | [Coordination](coordination.md) |
| Is progress current? | Compare previous/current times and concrete changes at bounded checkpoints; diagnose stalls before replacing an owner. | [Checkpoints](checkpoints.md) |
| Can interrupted work resume? | Preserve valid artifacts, read back uncertain effects, retain stop gates and use finite retry authority. | [Recovery](recovery.md) |
| Is the work already incorporated? | Compare ancestry, current files, trees and patch evidence before duplicate cherry-picks or replacement PRs. | [Reconciliation](reconciliation.md) |
| Does the evidence cover this revision? | Bind source, diagrams, formal proofs, tests, review and delivery to the exact subject and original criteria. | [Verification](verification.md) |
| Has the result arrived? | Separate persistence, attachment, recipient readback and canonical incorporation. Report denominators and remaining obligations honestly. | [Delivery](delivery.md), [record format](record-format.md) |

Product CI, release, deployment and customer acceptance remain separate. The skills do not invent unlimited usage, paid access, publication permission or authority over another owner. A coverage map describes intended practice; it does not prove an agent followed it.

[The execution plan](execution-plan.md) adds explicit main features/extensions, prerequisite order, M/VM and W/V responsibilities, bounded correction and final integration acceptance. Conditional evidence guidance covers [formal obligations](formal-verification.md), [Pele diagrams](diagrams.md) and [model/harness evaluation](benchmarks.md). These are operating practices; the CLI does not enforce role independence or execute these tools.
