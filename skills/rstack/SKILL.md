# rstack

Restore the original request, latest steering and current authority. Reuse the existing owner and register. Load the installed pstack adapter and matching playbook for substantive engineering; record what actually loaded. Rstack adds outcome-management practices without changing pstack's identity or granting external authority.

Choose only the relevant leaf:

- Intake or ambiguous completion: [outcomes](../rstack-outcomes/SKILL.md).
- Coordination or Cloud Task admission: [coordinate](../rstack-coordinate/SKILL.md).
- User check-in, elapsed work or possible stall: [checkpoint](../rstack-checkpoint/SKILL.md).
- Cancellation, interruption, denial or uncertain send: [recover](../rstack-recover/SKILL.md).
- Existing local work or possible duplicate PR: [reconcile](../rstack-reconcile/SKILL.md).
- Source, Pele diagrams, Lean, optional Aristotle, Verus, benchmarks or independent review: [verify](../rstack-verify/SKILL.md).
- Recipient delivery or completion reporting: [deliver](../rstack-deliver/SKILL.md).

- Artifact sharing and audience/privacy checks: [rstack-publish-privacy](../rstack-publish-privacy/SKILL.md).
- Shared job capacity, admission, cleanup and recovery: [rstack-executors](../rstack-executors/SKILL.md).
- Shared MCP client isolation, cancellation and reconnect: [rstack-mcp](../rstack-mcp/SKILL.md).
- Physical keyboard, dictation and peripheral acceptance: [rstack-input](../rstack-input/SKILL.md).
- Full-thread mailbox triage and rule arrival checks: [rstack-mail](../rstack-mail/SKILL.md).
- Tab, group and bookmark coverage: [rstack-browser-library](../rstack-browser-library/SKILL.md).
- Account, device and runtime security coverage: [rstack-estate-security](../rstack-estate-security/SKILL.md).

Return a delivered result or exact dependency and resumption trigger. Do not create a competing audit, supervisor, schedule or owner. See [the feature map](../../docs/feature-map.md) for the offline helpers and their limits, and [tool workflows](../../docs/tool-workflows.md) when selecting pstack, gstack or local ClawSweeper.

For multipart work, use [the execution plan](../../docs/execution-plan.md): explicit main features and extensions, ordered acceptance checklist, manager/independent verifier and bounded worker/verifier pairs. Review the plan before dispatch and the combined revision before final acceptance. Use the existing orchestration tools; this adds no dispatcher.

For authorized company work spanning domains, use [the company operating loop](../../docs/company-operations.md), [capability contracts](../../docs/company-capabilities.md) and [operating-unit template](../../templates/company-operating-unit.md). Preserve existing domain owners and systems. These procedures do not establish complete company readiness or grant external authority.

For recurring qualification failures, select the relevant section of [workflow qualification](../../docs/workflow-qualification.md). It covers history extraction, planning, benchmark/checker adequacy, runtime adoption, recovery, operational evidence and owner handoffs. For a bounded state-machine example, use [formal architecture](../../docs/formal-architecture-example.md). These references add no runtime enforcement or external authority.
